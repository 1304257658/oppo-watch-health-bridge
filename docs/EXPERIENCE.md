# 实验经验与排错

这些是一次授权个人互操作实验的观察，不是所有设备的通用结论。本文不含账号信息、设备标识、健康明细、凭证、原始日志或 APK 内容。

## 1. 先确认数据链路

手表配对、手机数据、账号云同步、另一台设备看到历史记录，是不同环节。不要为了让模拟器显示数据而解除手机与手表配对、重置手表。

本次手机端与模拟器端分别开启云同步后，模拟器能够显示非零历史记录。它证明云端存在可同步记录，不证明数据完整、实时，也不证明每一种指标都有独立公开接口。

## 2. 登录失败不能仅凭文案定因

“Server maintenance in progress” 本身不能证明服务器维护，更不能直接推导为缺失 OPPO 服务或反模拟器检测。

实验遇到的 DNS、代理、WebView 加载、模拟器系统 UI 卡顿，应分别取证。主机代理可用不代表 Android 应用能解析同一域名。模拟器访问主机回环服务通常有专用宿主地址，不能把主机 127.0.0.1 原样当成 Android 主机地址。

本次采用模拟器系统 HTTP 代理后登录页面改善，但需保留 TLS 验证；不应通过关闭证书验证掩盖网络问题。代理和安全设置的变更应独立授权，且不上传配置或认证信息。

## 3. 模拟器兼容性与稳定性

- 本次使用官方 Android Emulator；更新到隔离安装的新版本后短期稳定性改善，不代表长期运行已验证
- ARM64 应用与 x86_64 系统的兼容性必须用实际执行确认，不能只看 ABI 声明
- 系统 UI 无响应可能是资源、软件渲染或启动负载问题；降低分辨率在本次没有稳定改善
- 一个附属网络仿真进程发生过崩溃；隔离特性后改善仅是本次观察，不是通用关闭建议
- 使用独立实验 AVD、独立 ADB 端口、独立下载/缓存目录，避免影响已有开发环境
- 即使实验文件指定到数据盘，操作系统仍可能在系统盘写入崩溃报告；不能承诺“系统盘零写入”

## 4. 动态探测的失败层级

本次曾在脚本创建阶段失败，此时 Java bridge 尚未运行。因此不能把 TransportError 直接解释为 Java 不可用。

小型纯 JavaScript/RPC 探测先成功后，再分段加载较大 bridge 并执行，最终确认 Java 可用。这是定位加载层问题的经验，不是绕过授权的办法。本公开仓库不附动态注入组件、权限变更脚本或凭证提取器。

任何临时模拟器安全设置变更都应提前说明、留存非敏感恢复基线，并在结束后验证恢复；恢复失败时不能报告整体成功。测试中的恢复状态仅为模拟对象，不证明真实设备已恢复。

## 5. “能请求”与“能长期运行”不同

经用户亲自操作，本地一次限定读取成功。这个结果不等于云端读取成功，也不等于无需再次登录。原实验成功请求不需要额外读取 ssoid、主账号令牌或刷新令牌。

静态分析发现刷新相关代码，只能证明应用包含此类逻辑，不能证明当前会话采用哪条分支、所需字段可获得、服务端允许独立客户端续期。观察到的 24 小时检查间隔不是 token 的有效期。

不要推断永久授权。实际到期、撤销、多设备互踢、轮换与并发刷新，均需专门设计和验证。

## 6. 云端不一定只有一台机器

代码执行工作区与桌面浏览器可能处于不同机器。一个环境启动 localhost 服务，另一个浏览器连接被拒绝，并不能证明回环服务坏了。

同一云端桌面上的回环网页可用后，仍需独立验证外网出口；本次外网探测被拒绝。应尊重环境访问限制，选择受支持的运行环境，不绕过限制。临时交互桌面也不能直接当作有持久磁盘、可靠调度和永不休眠的服务器。

## 7. 公开仓库应重新清理而非直接打包

只复制明确允许公开的源码与重新撰写的经验。删除账号/设备标识、真实响应、原始日志、数据库、截图、APK/DEX/二进制及厂商签名常量；保留假数据测试。不要以“私有仓库”代替凭证保管，也不要认为 `.gitignore` 能清理已经提交过的历史。
